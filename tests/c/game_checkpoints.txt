# M3 first-light checkpoints (no input).
#
# Each line is a scene the original displays undisturbed for several seconds:
#
#   <name> <framebuffer-hash> <palette-hash> [<hold>]
#
# The hashes are FNV-1a 64 over the 320x200 mode-13h index buffer and the
# 6-bit DAC values, in that order, seeded with the same offset basis the C
# engine uses (0xCBF29CE484222325).  They were taken from the stream recording
# of the original (tools/dosbox/stream.sh) at the end of each scene's fade and
# cross-checked against the DOSBox-X save states, which show the same settled
# palette.  The sequence is what the intro plays after start-up: the Webfoot
# logo, the two story screens, then the four attract vignettes.
#
# The gate requires the pairs in this order, each held for at least 60 ticks
# (3.3 s) of engine time.  A match means the C port drew the original's pixels
# with the original's palette, not merely a similar screen.
#
# The optional fourth field pins the settled-to-next-change hold.  The attract
# vignettes all advance on the original's 91-tick scene countdown (v_50EA and
# v_50EC reload 5Bh in the tick ISR); the observed 93 ticks are that countdown
# plus the two ticks to the next presented frame.  The stream recording's
# 137-tick figure is inflated because its seam present runs before the
# countdown and makes the ISR lose BIOS ticks.  A "-" means only the >=60-tick
# floor applies.
